## Validation and business rules by controller

### Auth

AuthService: verified + active + unsuspended account; session validation on every authorized request; login lockout; refresh rotation and replay revocation. Refresh/logout require double-submit CSRF.

### Users

UserService: own mutable profile; username uniqueness + 30-day cooldown; email token verification; public profile projection only; privacy flags respected by downstream services.

### Friends

FriendService: directional requests; reverse request can accept; block overrides friendship and private access; no self-action; actor must own/respond to the relevant request.

### Conversations

PrivateChatService + MessageActionService: active nonblocked pair, accepted access or eligible pending request; sequence visibility and per-user hiding; clientMessageId idempotency; search 2–100 chars.

### MessageRequests

MessageRequestService: receiver inbox; accept/reject/read by receiver; rejection prevents implicit renewal; explicit renewal requires confirm and eligible privacy/access.

### Groups

GroupService: active eligible members; invitation acceptance bounds visible history by join sequence; owner cannot leave; send idempotency; history enforces visibility intervals.

### AdvancedGroups

AdvancedGroupService: group roles, not SystemRole; Owner/Admin management; only Owner demotes Admin, transfers or dissolves; Admin can promote Member and remove Member; pins require service permission.

### GroupInviteLinks

GroupInviteLinkService: authorized management, expiry/revocation and removed-member checks; token only returned on creation; resolve then explicit confirm to join.

### Messages

MessageActionService: visible accessible message; sender-only edit within 15 minutes; nonblank ≤10000 chars; recall and forwarding reauthorize; one grapheme reaction (1–16 UTF-16 units); deleted/hidden/recalled visibility rules.

### MessageReceipts

MessageStatusService: visible message and eligible conversation; counts are server facts, never inferred from SignalR connectivity.

### ConversationStatus

MessageStatusService: eligible reader, monotonic/bounded cursor; acknowledge actual accessible message IDs only; never mark hidden/background content seen.

### Unread

UnreadSummaryService: server-derived main/request/notification counts filtered to actor-visible conversations.

### Files

FileService: purpose Message/Avatar; extension and signature checks; image 10 MiB, other file 25 MiB, avatar image 5 MiB; authenticated reads reauthorize attachment visibility.

### UserAvatar

FileService: actor-owned valid uploaded Avatar purpose; no arbitrary URL or file binding.

### Presence

PresenceService: privacy-filtered Online nullable and LastSeenAt; null does not mean offline.

### Notifications

NotificationService: recipient-only read; cursor timestamp + ID tie-break; mute settings require conversation access.

### Reports

ReportService: accessible User/Group/Message target; evidence captured server-side; actor can read own reports only.

### Appeals

AppealService: separate scope=appeal identity only for verified active suspended account; token restricted to /api/appeals; never install in normal chat session.

### Admin

AdminService/RetentionService: DB SystemRole Admin, not just route guard; claim/assignment and review eligibility checked in service; hold requires reason; read-only previews do not execute deletion.
